# Пайплайн: Gemini-изображение → готовый спрайт 32×32 (с прозрачностью)

Инструкция для сборки MCP-пайплайна, который превращает «псевдо-пиксель-арт» из
Gemini в чистый прозрачный спрайт `box×box` (по умолчанию 32×32), пригодный как
item-текстура мода.

Файлы рядом с этим документом:
- `sprite_pipeline.py` — ядро (все стадии как переиспользуемые функции + CLI)
- `mcp_sprite_server.py` — обёртка FastMCP (тулы `inspect_image`, `process_sprite`)
- `example_mandrake_32.png` / `_soft.png` — пример результата

---

## 1. Схема пайплайна

```
Gemini (Stage 0)
   │  высокое разрешение, фон «прозрачности» запечён как пиксели
   ▼
[1] загрузка RGB
   ▼
[2] background_to_alpha   — выбить фон в альфу (chroma | neutral | colored)
   ▼
[3] content_bbox          — реальный bbox контента, отбросить дальние strays
   ▼
[4] premult_downscale_fit — premultiplied-даунскейл, вписать в box, центрировать
   ▼
[5] save PNG (32×32, RGBA)
```

Каждая стадия — отдельная функция в `sprite_pipeline.py`, что удобно мапить на
отдельные MCP-тулы или собирать в один end-to-end тул.

---

## 2. Почему это не «просто resize» (ключевые подводные камни)

1. **«Прозрачный фон» от Gemini — это запечённая шахматка.** Модель рисует серый
   (или цветной) клетчатый узор как *картинку*, alpha остаётся 255 везде. Resize
   без удаления фона замешает клетки в цвет спрайта.
2. **Сначала альфа, потом даунскейл.** Фон не должен участвовать в усреднении при
   уменьшении, иначе края «грязнятся» цветом фона.
3. **Premultiplied alpha при ресемпле.** PIL не премультиплицирует — RGB прозрачных
   пикселей всё ещё «течёт» в края. Премультипликация это убирает.
4. **Кроп по реальному контенту ДО даунскейла.** Фон занимает ~50%+ кадра; без
   кропа спрайт ужимается в угол и теряет детали. Реальный размер иконки обычно
   сильно меньше холста.
5. **Тёмные тёплые тени vs тёмный холодный фон.** Если фон — тёмная сине-фиолетовая
   шахматка, тёмно-коричневые тени спрайта по цвету близки к ней. Спасает признак
   «тёплый» (R > B): такие пиксели не удаляем.
6. **Удаляем только фон, связанный с краем кадра** (connected-components от рамки),
   иначе выгрызаются серые/тёмные пиксели *внутри* спрайта (контур, тени).

---

## 3. Stage 0 — генерация в Gemini (самый важный рычаг качества)

Качество извлечения на 80% определяется тем, на каком фоне модель отдала спрайт.
По убыванию удобства:

- **Лучше всего: плоский насыщенный chroma-фон.** В промпте просить
  *«single centered object on a solid flat magenta (#FF00FF) background, no shadows,
  no checkerboard»*. Magenta/зелёный почти не встречается в природных спрайтах →
  кеинг идеальный, без ореола, тёмные тени не выгрызаются. Это `mode="chroma"`.
- **Приемлемо: нейтрально-серая шахматка** (то, что Gemini выдаёт на запрос
  «transparent»). Работает через `mode="neutral"`, но антиалиас-кайма требует
  аккуратного порога (уже зашит).
- **Хуже всего: тёмная цветная шахматка** (как в самом первом файле). Работает
  через `mode="colored"` + `warm_protect`, но тёмные части спрайта могут частично
  выгрызаться. Если видишь «дырявое» тело — перегенери на chroma-фоне.

Также проси: один объект по центру, без подписи/водяного знака, без декоративных
искр (они раздувают bbox; `drop_strays` их частично гасит, но лучше не плодить).

## 4. Stages 1–5 — функции и параметры

| Стадия | Функция | Вход → выход | Ключевые параметры |
|---|---|---|---|
| 1 | `Image.open(...).convert('RGB')` | путь → `np.uint8[H,W,3]` | — |
| 2 | `background_to_alpha` | RGB → `alpha[H,W]` | `mode`, `tol`, `warm_protect`, `close`, `fill_holes` |
| 3 | `content_bbox` | alpha → `(x0,y0,x1,y1)` | `drop_strays`, `dilate_frac` |
| 4 | `premult_downscale_fit` | RGB+alpha+bbox → `PIL RGBA box×box` | `box`, `hard`, `hard_thr` |
| 5 | `.save()` | RGBA → PNG | — |

Вспомогательная `detect_checker_palette` берёт цвет(а) фона из полосок по краям —
на ней строится автоопределение `mode`.

### Режимы выбивания фона (`mode`)
- `chroma` — один плоский насыщенный цвет; простой порог по расстоянию, потерь нет.
- `neutral` — серая шахматка; детект по низкой насыщенности (R≈G≈B) в полосе
  яркости; низкий нижний порог гасит и тёмно-серый антиалиас-ореол (внутренний
  контур спрайта защищён связностью с краем).
- `colored` — цветная шахматка; расстояние до палитры + `warm_protect` (тёплые
  R>B пиксели не удаляются).
- `auto` — выбрать по характеру палитры краёв (по умолчанию).

## 5. Запуск как CLI (быстрая проверка без MCP)

```bash
pip install pillow numpy scipy

# авто-режим, 32×32, резкая альфа
python sprite_pipeline.py input.png out_32.png --box 32

# мягкие края
python sprite_pipeline.py input.png out_soft.png --box 32 --soft

# под item 16×16
python sprite_pipeline.py input.png out_16.png --box 16

# принудительный режим / тюнинг
python sprite_pipeline.py input.png out.png --mode chroma --tol 70
python sprite_pipeline.py input.png out.png --mode colored --no-warm-protect
python sprite_pipeline.py input.png out.png --keep-strays
```

Печатает JSON: реальный размер контента, вписанный размер, % непрозрачных пикселей.

## 6. MCP-обёртка

Стек: **FastMCP 3.x** — стандартный способ строить MCP-серверы на Python
(декоратор `@mcp.tool`, `mcp.run()`).

### Установка
```bash
pip install fastmcp pillow numpy scipy
# либо официальный SDK (FastMCP встроен):  pip install "mcp[cli]>=1.27,<2"
```
> Примечание: официальный `mcp` готовит v2 (beta 2026-06-30, stable 2026-07-27) —
> ставь с верхней границей `<2`, пока не обновишь код под v2. Standalone `fastmcp`
> (3.x) — самостоятельный пакет и рекомендуемый путь для новых серверов.

### Файлы
Положи рядом: `sprite_pipeline.py` и `mcp_sprite_server.py`.

### Тулы
- `inspect_image(input_path)` → JSON: размер, есть ли реальная альфа,
  % прозрачности, цвет фона, **рекомендованный `mode`**. Зови первым, если не
  уверен в режиме.
- `process_sprite(input_path, output_path, box=32, soft=False, mode="auto",
  tol=34, drop_strays=True, warm_protect=True)` → JSON: путь, реальный размер
  контента, вписанный размер, % непрозрачных.

> Важно: тулы возвращают **JSON-строку**, а не dict — иначе некоторые клиенты
> (Claude Desktop) обрезают вложенные объекты.

### Запуск и регистрация
```bash
# локально, stdio (так его запускает Claude Desktop / Cursor)
fastmcp run mcp_sprite_server.py
# или
python mcp_sprite_server.py

# автоинсталл в клиент
fastmcp install mcp_sprite_server.py --client claude

# отладка в инспекторе
fastmcp dev mcp_sprite_server.py
```

Ручная регистрация в конфиге клиента (`claude_desktop_config.json` / `mcp.json`):
```json
{
  "mcpServers": {
    "gemini-sprite": {
      "command": "fastmcp",
      "args": ["run", "/abs/path/mcp_sprite_server.py"]
    }
  }
}
```

### Типичный сценарий вызова агентом
1. `inspect_image("gen.png")` → видит `recommended_mode: "neutral"`.
2. `process_sprite("gen.png", "icon_32.png", box=32, mode="neutral")`.
3. Читает JSON-ответ (реальный размер, % заполнения), при необходимости повторяет
   с другим `mode`/`tol`.

## 7. Известные ограничения и рекомендации

- **Тёмный объект на тёмном цветном фоне** → возможно выгрызание теней. Решение:
  генерировать на chroma-фоне (Stage 0), либо ослабить (`--tol` меньше +
  `warm_protect`).
- **16×16 для тонких высоких спрайтов** — деталей почти не остаётся; 32×32
  оптимально для такого силуэта.
- **Резкая альфа (`hard`)** даёт чистый item-look; **`soft`** мягче, но на тёмном
  фоне может казаться «дымчатой». Для MC-предметов обычно `hard`.
- **Декоративные искры/водяной знак** — `drop_strays` отбрасывает только дальние
  (через крупнейший блоб); близкие к спрайту искры остаются. Лучше не генерить их.

## 8. Идеи расширения пайплайна (по желанию)

- **Палитро-квантизация** под палитру мода (например, ограничить до N цветов через
  `Image.quantize`) — единый стиль ассетов.
- **1px-контур** (dilate alpha − alpha, залить тёмным) — классический item-outline.
- **Batch-тул** `process_folder(dir)` — пройтись по папке генераций.
- **Контроль-сетка**: тул, который рисует спрайт на чекере и на тёмном фоне рядом
  (как делалось при отладке) — быстрый визуальный QA внутри агента.
- **Прямой вызов Gemini-генерации как ещё один MCP-тул** в начало цепочки —
  тогда весь путь «промпт → готовый PNG» внутри одного агентского флоу.
