# Грамматика векторов

*Капстоун. Под Конституцией (закон) и Моделью данных (исполнение) лежит это — арифметика, к которой сводится всё: фракции, боссы, захват амулета, успех и провал ритуалов.*

## Различие, на котором держится всё

Мы говорили «вектор» в двух разных смыслах, и пока их не разделить — вопросы не имеют ответа.

> **Вектор действия (Act)** — что ты сделала. Дельта. Транзиентный, вычисляется на каждое действие, не хранится.
> **Векторы состояния (State)** — в каком положении мир и твои привязки. Накопитель. Хранится постоянно.

Мост между ними — **интеграция**: вектор действия записывается в векторы состояния. Это и есть «при каких условиях меняются». Половина твоих вопросов расходится по этой границе: вектора действия *не угасают* (их нет в памяти), угасает только состояние; на успех ритуала влияет состояние, а результат ритуала *есть* его вектор действия.

---

## 1. Какие вектора храним

**Вектор действия (Act) — оператор, не хранится.** Вычисляется из свойств реагентов/источника:
```
Act {
  domain: Map<Correspondence, float>   // {forest:0.8, death:0.2} — реагенты смешиваются
  reciprocity: float ∈ [−1,+1]          // −1 взятие/изъятие … +1 дар/подношение
  binding:     float ∈ [−1,+1]          // −1 высвобождение/разрыв … +1 связывание/печать
  defilement:  float ∈ [0,1]            // осквернение: убийство родни, порча древнего/священного
  magnitude:   float                    // масштаб (саженец ≪ древняя роща)
}
```

**Состояние (State) — хранится в трёх якорях (из Модели данных):**
```
Bond.disposition { debt, resentment, fear, loyalty }   // + sealIntegrity (для амулета)
ChunkSoulData.disturbance: Map<Correspondence, float>  // потревоженность ПО ДОМЕНАМ
PlayerSoulData { totalDebt, marks[] }                   // marks{domain, scope, severity}
```

Ключевая правка против Модели: `disturbance` теперь **по доменам**, не скаляр. Иначе нельзя ответить, *какой* босс отвечает и *какая* фракция злится. «Лесной долг региона» = `Σ disturbance[forest]` по чанкам.

## 2. Как они связаны (граф)

```
свойства реагентов ──Σ──► Act ──интеграция──► State ──чтение──► фракции
   (датапак)         (×время/место)  (дельта→накопитель)        боссы
                                                                 захват
                                                                 успех ритуала
```
Это DAG: реагенты порождают `Act`; `Act` модулируется контекстом (фаза луны, потревоженность места — «расстановка корреспонденций в пространстве и времени»); `Act` интегрируется в `State`; `State` читают все потребители. **Никто не пишет в `State` напрямую — только через `Act`.** Это и держит систему согласованной.

**Карта интеграции** (как `Act` становится дельтой состояния):
```
domain-вес w = Act.domain[D]              // вклад в домен D
debt        += max(0, −reciprocity) · magnitude · w     // взятие создаёт долг
loyalty     += max(0, +reciprocity) · magnitude · w     // дар растит верность
resentment  += defilement · magnitude · w               // осквернение растит обиду ПО ДОМЕНУ
seal/sealIntegrity ← f(binding)            // связывание печатает; разрыв рвёт
disturbance[D] += (|interaction|) · magnitude · w        // место запоминает по домену
```
`resentment` пишется во *все* привязки домена D (солидарность родни) — поэтому убийство лесного духа точит твой лесной амулет (захват из прошлого разговора падает сюда автоматически).

## 3. При каких условиях меняются

**На завершении действия** (ритуал, варка, добыча, убийство): вычислить `Act`, интегрировать.
**Непрерывно** (тик/период):
```
seal != null:         debt += drawRate · dt            // амулет тянет
debt не гасится:       resentment += k·f(debt) · dt     // долг копит обиду
угасание (см. ниже)
```
**На событиях** (пишутся в `ledger`): `BETRAYED` (убил родню) → скачок `resentment` по домену; `APPEASED` (ритуал-подношение, `reciprocity>0`) → `resentment↓ loyalty↑ sealIntegrity↑`; `FED`; `SPOKE`.

## Угасание — асимметричное, и это принципиально

Равномерный спад в ноль *стёр бы петлю* (Статья III): долг стал бы бесплатно прощаемым, мир — креативом. Поэтому угасает не всё и не одинаково:

```
resentment   → медленно к ПОЛУ, заданному (debt + активные marks)
                время лечит внимание, но не ниже того, что оправдано долгом
disturbance  → медленно оседает (мир прощает, если оставить его в покое)
                НО древние/высокомагнитудные шрамы оседают много дольше
debt         → НЕ угасает сам. Гасится только дарящими действиями (reciprocity>0)
loyalty      → медленно к baseDisposition, если не поддерживать (связь надо кормить)
sealIntegrity→ медленно растёт при низком resentment и сильной ведьме,
                но навсегда capped ниже после каждого почти-разрыва (шрам печати)
```

###
context
Это прямой ответ на «угасают ли вектора»: внимание мира — да, твой долг — нет. Ведьма, переставшая антагонизировать лес, увидит, как стражи успокаиваются и охотники расходятся (resentment и disturbance оседают). Но древняя роща, что она вырубила, оставит шрам надолго, а долг по носимым амулетам не растворится сам — его надо *отдать*. Время отводит взгляд; счёт остаётся.

## 4. На что влияют

```
Bond.disposition  → поведение PresenceEntity (utility-AI), выбор реплики, предикат «счёта»
sealIntegrity     → состояние амулета (баф → холодеет → дебаф → разрыв наружу)
disturbance[D]    → spawn-вес присутствий домена D + ПОРОГ боссa домена D
totalDebt + marks → «жар» фракций (охотники сходятся), общая враждебность мира
всё перечисленное → модификаторы успеха ритуала (раздел 6)
```

## 5. Как LLM меняет поведение групп (по векторам)

Жёстко по Статье V.5: **детерминированное ядро решает, LLM — ограниченный слой голоса/выбора поверх, никогда фундамент.**

Вектора задают **детерминированный «настрой» группы**: `disturbance[D]` места + агрегат диспозиции его `rootedBonds` → общий вектор мотиваторов на всю группу. Utility-AI выбирает *тактику* (роиться, скрадывать, засада, отступить, вступить в переговоры) из этих чисел. Это и есть настоящий драйвер поведения — он работает без всякой LLM.

Роль LLM — потребитель *тех же* векторов, не авторитет. Из состояния собирается компактный **бриф группы**, и он же — контекст для LLM:
```
GroupBrief {
  domain, moodVector{resentment,fear,loyalty},
  grievanceWithPlayer,            // из ledger: что игрок сделал именно им
  allowedIntents: [...]           // ОГРАНИЧЕННОЕ меню, заданное тактикой ядра
}
LLM → { chosenIntent ∈ allowedIntents, line, targetHint }
     → валидация по allowedIntents → исполнение ядром
```
LLM **модулирует выбор внутри границ и озвучивает** его — она не водит бой свободно. Вектора задают рамки и фичи; LLM выбирает реплику и intent *внутри* меню, которое ядро уже отфильтровало по настрою. Нет LLM или она вернула мусор → ядро берёт `chosenIntent` по argmax утилити, реплику — из индексированного пула. Так LLM физически не может выломать тон: её выход ограничен векторами-производным состоянием и белым списком намерений.

## 6. Влияют ли на успех ритуала — да, успех есть функция векторов

Успех/качество ритуала **вычисляется из состояния**, а не из плоского броска:
```
success ← align(Act.domain, состояние домена)        // в гневном домене — сопротивление
        · standing(caster, домен)                     // низкий debt + высокий loyalty → льётся
        · placePenalty(disturbance места)             // мутное место искажает результат
```
Следствия, которые заставляют игрока *читать* состояние перед действием (Статья I.5):
- высокий `resentment` домена → связывающие ритуалы в нём **сопротивляются** (дух дерётся с печатью), подношения — **легче**;
- высокий `loyalty` / низкий `debt` → лучший выход, ниже шанс провала;
- мутный чанк искажает: вектор «загрязняется» фоновым состоянием.

Мудрая ведьма сверяет настрой леса (по знакам в снах, по поведению присутствий) *до* того, как пытаться лесную привязку.

## 7. Провалы ритуалов и зелий — есть, и они не рандомная кара

Провал — это **вектор, разрешившийся не туда** (Статья II.6: никакого random там, где нужна логика). Режимы провала зависят от того, *как и почему*, а не от плоского fail-roll:

- **Рассогласование** — `Act` плохо собран → эффект разрешается в сторону *фактического* вектора, не задуманного. Хотела защиту, реагенты ушли в взятие → получила взятие. Тут нет «провала» — есть «получила ровно то, что на деле попросила». Самый элегантный режим: система всегда считает реальный вектор, игнорируя намерение.
- **Сопротивление** — высокий `resentment` домена → дух отказывает или инвертирует. Откат пропорционален обиде: сорванная привязка в гневном лесу спавнит то самое присутствие, что ты вязала, теперь враждебным (питает `disturbance` → это и есть конвейер боссов/захвата).
- **Перебор** — `magnitude` выше твоего standing → долг берёшь всё равно, результат частичный/сломанный, а неоплаченный излишек падает на тебя **меткой на себе**. Перебор клеймит. Это и есть «отложенный штраф» из прошлого разговора, теперь заземлённый: перебор = мгновенный долг, право на который не заслужено.
- **Осквернение** — провал высоко-`defilement` действия → скачок `resentment` + немедленное враждебное воплощение. Домен отвечает.

Зелья — та же грамматика в малом масштабе (варка = ритуал низкой `magnitude`): рассогласованные реагенты → неверный (вычисленный) эффект, испорченное/проклятое зелье с малой меткой или мелким присутствием. Последствия пропорциональны `magnitude`: зелья — мелочь, ритуалы — крупно, великие ритуалы — босс-тир.

**Главный принцип: провал питает петлю, а не тратит материалы впустую.** Сорванный ритуал поднимает `disturbance`/`debt`/`resentment` — провал делает мир *живее и опаснее*, не «попробуй ещё раз». И провал телеграфируется (знаки во сне, возбуждение присутствий перед кастом в гневном домене) — катастрофа есть выбор проигнорировать состояние, как и везде.

## 8. Расплата: всё — арифметика над этими векторами

Ради чего весь разговор. Каждая обсуждённая система — это чтение `State`:

| Система | Чем оказывается |
|---|---|
| **Гнев мира** | `disturbance[D]` перешёл порог |
| **Охотники/инквизиторы** | f(`totalDebt`, тяжесть `marks`) — целят в *сделанное*, не в *суть* |
| **Чужие ковены** | конкуренция за `SpiritType`/домен |
| **Босс домена** | `Bond` с огромными `debt/resentment`, триггер `disturbance[D] > T` |
| **Призыв босса** | намеренный `Act` высокой `magnitude`+`binding`; `Act.domain` решает *кто* ответит |
| **Захват амулета** | `resentment` точит `sealIntegrity` до разрыва наружу |
| **Успех ритуала** | align · standing · placePenalty |
| **Провал** | вектор разрешился не туда |

Восемь систем — один набор полей. Это «язык», а не «набор слов».

## Что закрыл дефолтами (переопределяемо)

Как договаривались каждый раз — принял разумные значения, крути под себя:

1. **Оси полярности — три** (`reciprocity`, `binding`, `defilement`). Минимум, порождающий пространство. Можно добавить ось (напр. `volatility` — непредсказуемость домена), но каждая новая ось — новая сложность для игрока (Статья VI).
2. **Угасание — линейное к полу/базе**, кроме `debt` (не угасает). Можно сделать экспоненту; пол `resentment = debt + marks` не трогай — он держит петлю.
3. **`disturbance` по доменам на чанк** (уточнение Модели). Региональная агрегация для боссов = сумма по чанкам в радиусе.
4. **Пороги** (boss `T`, инверсия печати, «счёт») — заданы числами, не выведены. Это ручки баланса, единственное место, где подбор руками законен.
5. **`Act` модулируется временем/местом** (фаза луны, фоновая `disturbance`). Можно отключить, если не нужен пространственно-временной слой ритуалов.
